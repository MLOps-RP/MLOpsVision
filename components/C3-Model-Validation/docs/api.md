# HTTP API (`mqvg.api`)

A thin FastAPI wrapper around `mqvg.workflow.validate_and_report`. It adds **no validation
logic**: the same model, data and profile give the same answer as the command line. The answer
is always a **recommendation**; the API has no endpoint that deploys, promotes or rolls back
anything (a test checks the route list).

```
python -m mqvg.api            # serves on 127.0.0.1:8000
```

The machine-readable contract is [api_openapi.json](api_openapi.json) (generated by
`scripts/export_openapi.py`; a test fails if the API changes without regenerating it). Other
components should integrate against that file. Within `/v1` the intent is additive changes
only; this is a stated intention, not something that has been exercised yet.

## Security: read this first

Validating a model loads it, and **loading a pickle runs the code inside it**. An endpoint that
loads a model from a path is therefore a code-execution surface. The API is restricted by
construction, but none of this makes it safe to validate untrusted models.

| Risk | What the API does |
|---|---|
| Reading arbitrary files (`../../etc/passwd`, `C:\...`, UNC paths, NUL bytes) | Every path is relative to `MQVG_ARTIFACT_ROOT`, resolved, and rejected if it leaves the root. Symlinks and Windows junctions that escape the root are rejected (tested). A file must exist; a missing file is a 422, not a verdict. |
| Loading a malicious model | Only profiles that scan the model file **before** loading it, and that refuse to load a flagged file, are run by default (`extended`, `extended_hidden_groups`). `default`, `strict` and `hidden_groups*` are refused with a 422 unless the operator sets `MQVG_ALLOW_UNSCANNED_PROFILES=true`. A profile with `refuse_at: never` does not count as scanning. |
| Choosing a config file | The client names a profile; it can never send a config path or config content. Unknown fields in the request are rejected. |
| Unauthenticated use | Every endpoint but `/health` needs the `X-API-Key` header (constant-time comparison). With no key configured the API **fails closed** (503) unless `MQVG_ALLOW_NO_AUTH=true`. The key is never logged, returned or shown in `repr`. |
| Exposure | The server binds to loopback; `MQVG_HOST` elsewhere requires `MQVG_API_KEY`. |
| Reading other runs' files | Run ids must be 32 hex characters; anything else is a 404/422. |
| Leaking internals | A crash returns a generic 500 with the run id; the traceback stays in the server log. |

What the scan does and does not do is described in [extended_checks.md](extended_checks.md): it is
a static allowlist, not a sandbox. Run the API as a low-privilege user, ideally in a container with
no network and no secrets, and only validate models from sources you trust. The API provides **no
TLS, rate limiting or per-client credentials**: put it behind a reverse proxy that does.

## Configuration (environment)

| Variable | Meaning | Default |
|---|---|---|
| `MQVG_ARTIFACT_ROOT` | **required.** Folder the API may read model, data and metadata files from | none |
| `MQVG_API_KEY` | the key clients send in `X-API-Key` | unset (API answers 503) |
| `MQVG_REPORT_DIR` | where each run's `result.json`, `report.md`, `summary.json` are written | `mqvg_api_reports` |
| `MQVG_CONFIG_DIR` | folder of profile `*.yaml` files | the repository's `configs/` |
| `MQVG_DEFAULT_PROFILE` | profile used when a request names none | `extended` |
| `MQVG_ALLOW_UNSCANNED_PROFILES` | permit profiles that load models without scanning | `false` |
| `MQVG_ALLOW_NO_AUTH` | serve without a key (local development only) | `false` |
| `MQVG_QUEUE_TIMEOUT` | seconds a request waits for the validation lock before a 503 | `300` |
| `MQVG_HOST`, `MQVG_PORT` | listen address | `127.0.0.1`, `8000` |

## Endpoints

| Method and path | Purpose |
|---|---|
| `GET /health` | liveness, gate version, authentication mode (open) |
| `GET /v1/profiles` | profiles, which scan model files, which this server will run, their weights |
| `GET /v1/checks` | the check catalogue (id, layer, direction, unit) |
| `POST /v1/validations` | validate one candidate; **201** with the summary and a `Location` header |
| `GET /v1/validations` | recent runs, newest first (`?limit=1..200`) |
| `GET /v1/validations/{run_id}` | the full auditable `ValidationResult` (every check, scorecard, rules, configuration) |
| `GET /v1/validations/{run_id}/summary` | the compact summary |
| `GET /v1/validations/{run_id}/report` | the unified Markdown report |

### Request

```json
{
  "candidate_id": "churn-2026-10",
  "model_path": "models/churn/model.joblib",
  "eval_data_path": "models/churn/eval.csv",
  "metadata_path": "models/churn/metadata.json",
  "train_row_hashes_path": "models/churn/train_row_hashes.txt",
  "target_column": null, "positive_label": null, "sensitive_columns": null,
  "profile": "extended"
}
```

Only `model_path` and `eval_data_path` are required. The evaluation CSV holds the features
**and the true labels** and must be separate from the training data.

### Response (201)

```json
{
  "run_id": "5b29e3aac18a4be49936b2f323a991ba", "candidate_id": "churn-2026-10", "profile": "extended",
  "decision": "PROMOTE", "action_mode": "RECOMMENDATION", "summary": "...",
  "mqs": 86.9, "mqs_lower_bound": 86.9, "mqs_sufficient_evidence": true,
  "overall_coverage": 1.0, "provisional": false,
  "dimension_scores": {"training_validity": 99.9, "model_behaviour": 73.8, "operational_readiness": 100.0},
  "triggered_rules": [{"rule_id": "mqs_meets_promote_threshold", "kind": "score", "effect": "PROMOTE", "reason": "..."}],
  "check_counts": {"PASS": 22, "WARN": 3},
  "created_at_utc": "...", "result_url": "/v1/validations/5b29...", "report_url": "/v1/validations/5b29.../report",
  "notice": "This is a recommendation only. Nothing was deployed, promoted or rolled back."
}
```

`mqs` is `null` when the evidence is too thin to quote a score (`mqs_sufficient_evidence: false`);
`mqs_lower_bound` is then the figure to look at. A check without evidence is never reported as a pass.

### Errors

| Code | Meaning |
|---|---|
| 401 | missing or wrong API key |
| 422 | bad body, unknown or refused profile, path outside the root, file not found |
| 404 | unknown run |
| 503 | API key not configured, or the gate was busy for longer than `MQVG_QUEUE_TIMEOUT` (`Retry-After: 30`) |
| 500 | the validation crashed (see the server log with the run id) or a profile is misconfigured |

A candidate that is bad but readable is **not** an error: a corrupt, dangerous or incomplete
model is a normal 201 whose decision is HOLD or ROLLBACK, with the reasons.

## Example

```powershell
$env:MQVG_ARTIFACT_ROOT = "C:\path\to\artifacts"; $env:MQVG_API_KEY = "change-me"
python -m mqvg.api

curl.exe -s -X POST http://127.0.0.1:8000/v1/validations -H "X-API-Key: change-me" `
  -H "Content-Type: application/json" `
  -d '{\"model_path\":\"good/model.joblib\",\"eval_data_path\":\"eval.csv\",\"metadata_path\":\"good/metadata.json\"}'
```

## Behaviour and limits

- **Synchronous.** A request returns after the validation, typically seconds to a minute (a
  large model or evaluation set takes longer); there are no background jobs or webhooks.
- **One validation at a time.** Latency and CPU checks are timings, so concurrent runs would
  disturb each other. Further requests wait on a lock and get a 503 after `MQVG_QUEUE_TIMEOUT`.
- **Runs are stored on disk and never deleted** by the API; there is no retention policy.
- **No caching of results across identical requests**; each POST is a new run with a new id.
- The result is a snapshot of the files at request time. Latency, CPU and memory vary by
  machine and load, so two identical requests can differ slightly in score.
- Verified by `tests/test_api.py` (56 tests, one skipped when symlinks cannot be created on
  Windows; a directory junction is tested instead) and by a live run of the real server over
  HTTP. Not verified: behaviour behind a proxy, under load, or with very large files.
