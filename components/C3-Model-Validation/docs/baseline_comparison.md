# Baseline comparison: plain metrics gate vs the full gate

Generated by `scripts/baseline_comparison.py`. Every sample model was validated once per profile; the baselines read the F1, precision, recall and ROC-AUC checks from the same run, using the configuration's own `pass_at` limits.

- **F1 only**: promote iff F1 passes.
- **metrics only**: promote iff F1, precision, recall and ROC-AUC all pass (a typical evaluation script).
- **full gate (default)**: the default profile.
- **full gate (hidden_groups)**: hidden failure group check on, policy `hold`.

Ground truth is the fixture manifests: a model is a *defect* if a defect was injected into it (`injected_defect` is not `none`) and *clean* otherwise. `slow` is excluded because its expected decision depends on machine speed. A baseline that cannot compute its metrics counts as not promoted.

**The sample models were built by the project author, so this measures the gate against defects it was designed for, not defects found in practice. There are only two clean models, so the false-alarm figures are weak evidence.**

## Defects a plain metrics gate promotes

- **leaky**: Extra feature prior_high_income_flag equals the true label, flipped for 3% of rows, in both train and eval. Stopped by: full gate (default), full gate (hidden_groups).
- **good_incomplete_metadata**: Good model, but 11 metadata fields removed (seed, split, data hash, hyperparameters, versions, code commit, training metrics, ...). Stopped by: full gate (default), full gate (hidden_groups).
- **good_no_sensitive**: Evaluation data without the sex and race columns. Stopped by: full gate (default), full gate (hidden_groups).

## Reading this

- A metrics-only gate promotes models whose F1, precision, recall and ROC-AUC look fine but that leak the label, lack metadata or lack evaluation columns (listed above). Those need the training-validity and evidence checks.
- It also stops `overfit`, `biased` and `miscalibrated`, but only because a metric happens to be a WARN on this dataset (see `Metrics not passing`), not because it sees the overfitting, the unfairness or the miscalibration. The same weak metric makes it stop the clean `hidden_group_null` control (a false alarm). Its 'stopped' count therefore overstates what it detects.
- The F1-only gate stops only the model it cannot score.
- The default full gate does not stop `hidden_group`: every standard check passes. Only the profile with the hidden failure group check does.
- A model that a baseline cannot evaluate (for example a corrupt file) is stopped only because it cannot be scored; this is not a fair detection.
